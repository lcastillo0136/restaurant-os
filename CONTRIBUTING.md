# Contribuir a Restaurant OS

## Ramas

- `Master` conserva entregas aprobadas y no recibe desarrollo funcional directo.
- `feature/*` se usa para nuevas capacidades autorizadas.
- `fix/*` se usa para correcciones aisladas.
- Cada integración a `Master` debe pasar por Pull Request y revisión.

## Antes de proponer cambios

1. Lee `AGENTS.md` y la fuente de verdad en el orden indicado.
2. Declara fase, alcance, archivos y criterios de aceptación.
3. Ejecuta las validaciones y pruebas pertinentes; informa resultados reales y errores.
4. Comprueba secretos, datos personales y derechos de publicación de recursos.
5. No incluyas `.env` reales, dependencias, builds, bases de datos, respaldos ni perfiles de navegador.

## Historial

No reescribas historial publicado ni uses `push --force` sin autorización expresa. No muevas ni elimines etiquetas de entregas aprobadas.

## Licencia y recursos visuales

No hay una licencia open source aprobada. La visibilidad pública no concede permiso de reutilización. Los PNG oficiales de `design/reference/` son material interno excluido del historial hasta que exista autorización verificable de redistribución.
